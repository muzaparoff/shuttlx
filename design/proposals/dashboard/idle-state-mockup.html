Proposal 3 — Dashboard idle state ("dead state")

Surfaces: LastWorkoutCard.swift, WeekSummaryCard.swift + their empty states

The core insight. WeekSummaryCard renders the week as 7 × Circle().fill(count > 0 ? running : surface) — the exact "charting-library default" that reads as generic. Meanwhile the app already contains a segment-bar component in two places (hrVUStrip on iOS, MixtapeVUMeter on watch) that is far more distinctive, already themed, and used on exactly one screen. This proposal promotes it to a shared component and reuses it as the week chart — the "one parametric shape, many surfaces" doctrine, at negative code cost.

Second insight. A workout's interval segments are a tracklist. Mixtape has been sitting on a perfect structural metaphor and using it for decoration only.

Two of these five already exist as near-duplicate private implementations. Extracting SegmentBar(count:level:axis:bands:) makes this proposal roughly LOC-neutral or negative while adding two surfaces.

Motion. Idle-state cards animate on appear only (segments fill left→right / bottom→up over 0.35s, staggered 20ms), then are completely static. No loops. Respect accessibilityReduceMotion → straight to final state. The dashboard is the app's most frequently opened screen; a permanent animation there is a battery and attention cost with no informational payload.
